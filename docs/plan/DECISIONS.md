- 2026-11-13 — Menu law (user rule, applies everywhere in the UI, every module): the menu is grouped by function, never by "automatic" against "manual". A click on a menu item (and Enter on it, and its keyboard key) only selects it and shows its inspector: it never starts a computation, a file or folder dialog or a tool, whether the step is done or not. The inspector of a function holds everything about it, always in this order: title and description, status (done or not, last result), Parameters, Automatic (the button that runs it: "Run", "Run again" once done, or the dialog wording of the leaves that need an answer; it is the only way to run a function from the window) and Manual corrections (its tools, with the controls of the open one in the inspector; the viewport keeps the pointer for it). Leaving the function closes its tool. Aligners: the sub-group "Manual corrections" and the leaf "Move a tooth" left the menu (13 leaves, still 8 steps); Mark a tooth, Change a tooth number and Missing tooth are tools of Find the teeth, Tooth brush (key B, which selects Separate teeth and gum and opens the brush) and Clean borders of Separate teeth and gum, Rebuild a tooth of 3D teeth, Move a tooth of Final position; their commands stay registered for the CLI and the MCP server. The workspace draws every function from one table (`dc-workspace/src/function.rs`), so a new function follows the law by adding its entry. Spec: `docs/design/ui-spec.md` section 6.
- 2026-11-15 — Scans closed at import (user choice C): the study-model closure comes first, so the 3D view is a digital twin. Every imported open arch scan is closed with a flat base by `aligners.case.import-scans`, in the same undo step; the closed solid is THE case scan (view, save, bite, stamp, trim line, export). Deviation from the plugin, which closes only on request and with the tooth-mark frame: the import has no tooth marks, so the base is perpendicular to `autoseed::occlusal_axis` of the open scan (1.6-12.6° from the tooth-mark normal on the 4 real scans, never upside down; walls through teeth 69/0/0/10 border points against 77/0/0/8 for the plugin's frame). The scan as read stays the prefix of the closed blob (`AlignersState::scan_bases`, keyed by blob, carried by rigid moves); find the teeth, orientation, frame, segmentation, seed check, tooth measures, 3D teeth, gingiva, case analysis, setup, staging, shell frame, visits and study models read that prefix, so the real-scan oracles see the same input.
