# DentalCraft UI spec (v0.8 design pass)

Source of truth: `dentalcraft.figcraft` (pages **Screens**, **Components**, **Design System**). Tokens: `tokens.json`. PNG exports: `screens/`.
All sizes are egui points at 100 % scale; frames are 1920 x 1080.

## 1. Identity in one paragraph

Metaphor: the **curing light** and the **shade guide** of a dental bench.
- **Amber** (`accent/amber`, like the amber shield of a curing lamp) marks actions only: primary buttons, the open action on module cards, links. At most one amber filled button per view.
- **Curing blue** (`select/blue`) marks selection, focus and the current stage. Focus ring = `focus/ring`, 2 pt, outside the widget.
- Everything else is graphite (backgrounds) and enamel (text), so the dental model is the brightest object on screen.
- **Shade-tab shape** (radii 16/16/4/4, dark "handle" band with a mono code such as `AL`) is used for module cards, the logo tile and module chips.
- **B612 Mono** for every measured value (mm, degrees, stages, counts, paths, versions in tables). **Atkinson Hyperlegible Next** for all other text. **Phosphor Regular** icons via font.

## 3. Global layout rules

- Grid: 4 pt. Panel padding 16 (inspector), 20 (cards), 24 to 48 page gutters.
- Separation by 1 pt `border/subtle` lines and background steps (`canvas` < `panel` < `raised`), never by shadows, except floating things over the 3D view (e1) and dialogs (e2).
- Hit targets: 36 pt buttons in panels, 44 pt on Home/dialogs, 48 pt for the single sign-in call to action; icon buttons 32 to 36 pt; menu rows 28 to 36 pt (desktop pointer UI, all rows are full-width hit areas).
- Status always = icon + word (or shape + label in the viewport legend). Colour never carries meaning alone.
- Light theme is the same layout with the `Light` mode of the Color collection (see `01 Home (light)`, `05 Aligners workspace (light)`).

- Top bar: logo tile (back to Home), module chip (`AL` + "Aligners"), project name + extension, the save status (dot + text, see **Saving**); spacer; Undo / Redo (ghost, Redo disabled when stack empty), primary Save (always enabled), divider, Help, avatar.
- **Saving**: every change of the case makes the project unsaved, whatever made it (the brush, the tooth marks, a setting, a step, undo, redo: a change is a new state on the undo stack). Save (button, Ctrl+S) writes the case as it is then, atomically (`.tmp`, fsync, rename, one `.bak`); a Save asked for while another save runs follows that one (never refused). A change that lands after Save is pressed (a brush stroke still running) stays unsaved and the automatic save writes it.
  - **Automatic save**: a project that has a file and was not opened read-only saves itself 2 s after the last change (each change starts the timer again); never while a job that changes the case runs, a save runs or a dialog is open: it follows as soon as they end. A project never saved has no file: it does not save itself and nothing asks for a file; after the first Save it saves itself. A file opened read-only is never written by itself.
  - Status after the project name, quiet (8 pt dot + 12 pt `text/secondary`, no toast when it works): "Saving…" (`text/secondary` dot), "Saved" (`status/success`), "Unsaved changes" (`accent/amber`), "Not saved" (`status/danger`: the last save of the case as it is failed; it is tried again at the next change or with Save). Tooltip: "Every change is saved by itself a couple of seconds after you stop.", or without a file that can be written "Changes are not saved by themselves until the project is saved to a file that can be written: use Save.". A failed save is never silent: an error toast that stays until closed ("Save failed" or "Automatic save failed", with the reason). The user's Save also shows the "Project saved" toast.
  - **Leaving** (Home, Ctrl+W, closing the window): a project with a file is saved first, then it leaves, without a question; one never saved or opened read-only asks "Save the changes to <name> before leaving?" (Save, Don't save, Cancel), and so does a save that fails while leaving. The window stays open until then.
- Left menu: filter field (32, `/` shortcut) then the tree (section 6). Footer: workflow progress (`3/9` mono + success bar: the steps done out of the nine steps of the workflow, section 6).
- Viewport overlays (absolute, 16 pt inset): toolbar (views Occlusal/Front/Left/Right/Back as text segments; **arches** Upper / Lower as two toggle segments, see below; display Solid / Transparent / Wireframe; Measure, Angle, Section; layer toggles Tooth colours, Tooth marks, Tooth numbers, Contact map; marks Attachments, IPR, Target), tooltip pattern (label + mono shortcut), view-info pill, **view cube** 100 x 100 top-right, tooth callout with leader (selected tooth 13: buccal, rotation, remaining), legend bottom-left (shape + label for selected tooth, final position, attachment, IPR), scale bar bottom-right (10 mm). IPR values in mono magenta-bordered tags.
- **Arch selection** (viewport toolbar, right after the view segments, a separator on each side): two toggle segments **Upper** / **Lower** (`ws-arch-upper`, `ws-arch-lower`; same text-segment style as the views, selected = `bg/hover` and semibold; role checkbox for screen readers; tooltip "Show or hide the upper arch" / "...lower arch"). A hidden arch is not drawn, not picked (hover and the manual tools), has no tooth number chips and no seed gems, and its stage 0 ghost and seed markers are hidden with it. The choice is kept for the workspace session (not saved in the `.dcprj`). The caption chip shows "Upper jaw" / "Lower jaw" / "Both jaws". Headless renders (CLI/MCP) choose arches with `view.set {"visible": [...]}`, independent of `view`/`preset`. Tooth number chips follow the teeth at the stage shown (anchor moved by the tooth pose) and sit on the crown of the 3D teeth or, in Scan view, on the crown painted on the scan. Renders also take `model` (`scan` | `teeth`) and `stage` (integer): the CLI defaults to the 3D teeth at the initial position, the app bridge to what the viewport shows (model and stage); the raster draws scans at rest whatever the stage.
- 3D colours: enamel `model/enamel` with `model/enamel-shade` 1.5 pt outline; gingiva `model/gingiva` (palate at 45 % opacity); selected tooth 3 pt `select/blue` outline; target (setup) positions as a translucent ghost `model/target` at 25 % (see "Final position: arch line and final ghost"); arch line `model/arch-line`; attachments `model/attachment`; IPR planes `model/ipr`.

The IPR totals per arch are in the result lines of Final position (section 6).

## 6. Aligners left menu tree (i18n)

**Menu law** (user rule, 2026-11-13, for every module and every part of the UI; recorded in `docs/plan/DECISIONS.md`):

- The menu is grouped by **function**, never by "automatic" against "manual". A function is one leaf; its manual corrections are not menu entries but tools of its inspector.
- A click on a leaf (and Enter on a focused row, and a key of the keyboard sheet) only **selects** it and shows its inspector on the right. It never starts a computation, a file or folder dialog or a tool, whether the step is done or not.
- The inspector of a function holds everything about it: its parameters, the button that runs it ("Run", or "Run again" once done) and its manual corrections. That button is the only way to run a function from the window; the CLI and the MCP server run the commands by id.

The menu is for the dentist and the technician: six groups and 14 functions (leaves), two levels. Wording is plain, with no name of an algorithm. The other commands of the module (the single stages, the settings) are reached from the CLI and the MCP server only; the commands of the manual tools from the inspector of their function and from the CLI and the MCP server. A leaf is the command `aligners.<path>`; its Fluent keys are `aligners-menu-<path>` (label) and `aligners-desc-<path>` (description in the inspector), the dots turned into hyphens. A tool command keeps the same scheme (its description is the tooltip of its button).

Progress: the footer and the group rows count only the **nine steps** of the workflow, marked **step** below: Import scans, Find the teeth, Separate teeth and gum, 3D teeth, Case analysis, Bite, Final position, Aligners, Clinical review. The footer reads `done/9` (mono, with the success bar). A group row shows `done/total` of its own steps in mono; a group with no step (Production, Follow-up) shows no counter. Run everything automatically, Export for printing, Study models, Control visit and Re-plan are not steps: they are a shortcut, outputs and follow-up, and never count.

A leaf shows a check mark when the case holds its result: after a fresh run and after reopening the project (the module reads it from the case data; undoing a step takes the mark away). The leaves that leave nothing in the case (the exports, the re-plan, the pipeline) never show one.

### Inspector of a function

Every leaf has the same inspector, top to bottom. The workspace draws it from one table (`dc-workspace/src/function.rs`: per function its results, its parameters, a line about the run and its corrections); a function that is not in the table has its title, status and run button only, so a new function follows the law by adding its entry.

1. **Title and description** (the label and the `aligners-desc-*` of the leaf). A placeholder leaf says "Not available yet" and shows nothing else.
2. **Status**: the badge "Done" (success) when the case holds the result, otherwise "Not done yet" (neutral) for a step; a function that is not a step shows the badge only once done. Under it, what the last run left in the case where there is something to say: the result lines of Separate teeth and gum, the cards of Case analysis.
3. **Parameters** (section, only when the function has some): the role of the next import (Import scans), the options, the missing teeth and the teeth found (Find the teeth), the three separation sliders (Separate teeth and gum), the base settings (Study models). They are settings of the case, one undo step each.
4. **Automatic** (section): an optional line on what a run does, then the run button, full width: "Run" (primary) when not done, "Run again" (secondary) once done. The leaves that need an answer keep their wording and stay primary ("Choose the scan files…", "Choose the folder and export…", "Choose the scan of the visit…") and open their dialog only when it is pressed. The button is disabled while another command runs. Export for printing and Run everything add the line that says they can take a long time.
5. **Manual corrections** (section, only when the function has some): one button per tool (secondary, full width; it stays pressed, `select/soft` with a `select/blue` border, while its tool is open; hover gives the description and the key). A click opens the tool, a second click or "Close" closes it. The controls of the open tool are under the buttons, in the inspector: what to do with the pointer, the tooth, the values of the tool and Apply for the tools that change a chosen tooth (secondary, so that the run button stays the one amber button of the inspector). The viewport takes the pointer for the open tool (paint, place a mark, pick a tooth). Import scans lists here the scans of the case with how their role was decided, Confirm for a guess and the role control, then "Open scan: close with a base" (see below).

Selecting another function, a group, or nothing (Escape) closes the open tool and stops a numbering in order. Nothing selected: the inspector names the module and says "Select a function in the menu: its parameters, its run and its corrections are shown here." A group: its title and description, from the module.

What the run button does, for the leaves that have more to say:

- **Import scans** opens the file dialog (STL, OBJ, PLY). The button "Import scans" of the empty viewport does the same and selects the leaf.
- **Import scans, manual corrections** (the plugin's `oa.arch_set` and `oa.make_base`). Each is one undo step and changes the case only when pressed.

With one arch, or after the bite, the notice is not shown.

### Tooth numbers and the Alt+click brush (viewport)

- **Tooth numbers.** Every tooth that has a tooth mark, a measured tip or painted colours gets a **chip** over the viewport: 28 x 17 pt, radius 4, text mono 11 (points, so they scale with the UI scale), filled with the colour of the tooth (the same palette as the scan colours), the FDI number in black or white, whichever has the higher contrast (always at least 4.5:1), and a 1 pt outline of `border/strong`. The chip sits centred 6 pt above its anchor on the screen. Anchor, best first: the cusp tip measured by the teeth stage, else the top of the painted crown (centre of the crown raised to its highest point along the occlusal direction, as the plugin does), else the tooth mark. Chips that would overlap are moved up a few steps (the nearest to the camera keeps its place). A chip whose anchor is behind the scan (a ray from the camera meets the scan first) is hidden; so is that of an arch that is hidden. Teeth marked missing have none. They follow the stage shown (a moved tooth carries its chip). They are drawn in every state of the workspace, not only in Find the teeth, and are switched on and off by the layer toggle **Tooth numbers** (`ws-layer-numbers`, hash icon, in the layers group of the toolbar, on by default).
- **Alt+click chooses the brush tooth.** From any manual tool, and also when no tool is open (Find the teeth), Alt+click on: a tooth number chip (the topmost first), else a tooth mark gem (the nearest to the pointer within its drawn radius + 4 pt), else the scan (the tooth painted under the pointer; the bare gingiva chooses the gingiva, brush 0) selects Separate teeth and gum, opens its tooth brush if it is not the open tool and sets its tooth. Toast "Brush" with "Tooth 36" (or "Gingiva"). Alt+click never paints, places a mark or picks a tooth for the tool; the brush modifiers are unchanged (Shift gingiva, Ctrl fill the crown, Ctrl+Shift fill with gingiva). While the numbering in order is going on Alt+click only says to finish it first. While Alt is held, the chip or gem under the pointer is outlined in `select/blue`; the chip of the brush tooth is always outlined so. The hint of the brush controls says: "Alt+click on a tooth, its number or its mark: paint that tooth." On Linux some window managers take Alt+drag/click for moving windows: set the manager's window key to Super.

### Selecting a component and the gizmo (viewport)

- **Selecting.** With no manual tool open, a click on the viewport selects the component under the pointer: a 3D tooth, the gingiva of an arch, a scan (upper, lower, bite), or, on a scan whose teeth are coloured (Scan view), the tooth whose colour is under the pointer. A click on a tooth number selects that tooth. A click on empty space, **Esc** or the cross of the inspector section deselects. Selecting never runs anything (menu law); an open tool keeps the pointer (its clicks and strokes are unchanged) and Alt+click still chooses the brush tooth.
- **Drawing.** The selected component gets a 3 pt `select/blue` outline (`stroke.selected_tooth`) drawn around its silhouette on the screen, from any angle: solid around the parts that are seen, at 35 % around the parts other meshes cover. A tooth selected on the scan is outlined by a copy of its region. The component under the pointer gets a light `select/blue` tint.
- **Gizmo.** The selected component carries the transform gizmo at its centre, with a constant size on the screen: **W** move (arrows along X red, Y green, Z blue; squares in the planes; a free handle in the plane of the screen), **E** rotate (rings about the axes, the far half dimmed), **R** scale (a circle: the distance to the centre gives the factor). Ctrl snaps (0.5 mm, 5°, ×0.05). The value of the drag is shown next to the pointer. A drag is previewed on the meshes without changing the case; letting it go runs `aligners.components.transform` once: one undo step, saved and auto-saved like any change, the same command as the CLI and MCP. Esc during a drag cancels it.
- **What it changes.** A tooth moves and turns in the plan: its pose at the aligner shown on the timeline (stage > 0), as "Move a tooth" stores it (a collision with a neighbour gives a warning). At the initial position (stage 0) the move is refused: the teeth are where the scans have them, and a change would not show. Scale changes the size of its 3D tooth about its centre (0.5 to 2 times the built size), at every stage, until the tooth is built again; a tooth with a plan says that its final position and aligners must be computed again. The gingiva or the scan of an arch moves and turns the whole arch (scan, tooth colours and marks, 3D teeth, gingiva), as the bite registration moves it, and the arch stays up to date; a bite scan moves alone; neither can be scaled.
- **Inspector.** While a component is selected, the inspector starts with the section **Selected component**: its name ("Tooth 36" / "Dente 36", "Lower gingiva" / "Gengiva inferiore", "Upper scan" / "Scansione superiore", "Bite scan 1"), a cross to deselect, the gizmo mode (Move W / Rotate E / Scale R), a line on what the move does (or why a tooth does not move here), the fields Position X Y Z (mm, world frame), Rotation X Y Z (degrees, about its centre) and Size (teeth with a 3D tooth), each change one command (previewed while dragged), and Reset. The function of the menu follows under it.
- Keys: W E R are in the keyboard sheet (F1); they act only while a component is selected and no text field has the keyboard.

### Find the teeth (`aligners.teeth.find`)

The leaf runs the wrapper command `aligners.teeth.find`: the automatic numbering (`aligners.preparation.numbering.automatic`) first, then the automatic orientation (`aligners.preparation.orientation.automatic`), as **one undo step**. Each arch is numbered on its own. An arch that fails keeps the tooth marks it had and is named in a notice; the other arch gets its new marks.

Inspector (see "Inspector of a function"), section Parameters:

- The checkbox "Search also the third molars".
- Field "Missing teeth" (hint "e.g. 35, 45"; FDI numbers separated by commas, semicolons or spaces; helper "FDI numbers separated by commas. They are applied when you leave the field."). While you type, a wrong number shows the red message "Not a tooth number: <entries>. Use FDI numbers: 11 to 18, 21 to 28, 31 to 38, 41 to 48." The field is labelled for screen readers. The list is saved when the field loses focus and the text is valid; a wrong text is not saved. **Run is not blocked**: it uses the last saved list.
- Section "Teeth found": for each arch that has a scan, a title ("Upper arch" / "Lower arch") and a grid of 8 columns by 2 rows, one cell per tooth, right side of the patient first (upper: 18..11, 21..28; lower: 48..41, 31..38). Under the grids: "<n> teeth numbered" and the legend "Filled box: the tooth has a mark. Crossed box: the tooth is missing." - The run button runs the leaf with these settings: "Run", or "Run again" (secondary) once the case has its marks (as for every leaf).

Notices after a change of the tooth marks (toasts of the workspace, not part of the inspector):

- Automatic numbering drops what depends on the marks of that arch. Toast "Results cleared": "Cleared because the tooth marks changed: <list>. Run those steps again; Ctrl+Z brings the previous tooth marks and these results back."
- Manual mark edits (place, delete, sequence, clear) keep that data and mark it out of date. Toast "Results out of date": "Kept but out of date because the tooth marks changed: <list>. Run teeth and gum again, then the steps after it."
- An arch that could not be numbered: toast "An arch was not numbered": "<reasons>. That arch keeps the tooth marks it had; the other arch has its new ones."

Manual corrections (the tools of its inspector): **Mark a tooth** (`aligners.preparation.numbering.place-seeds`: a click on a tooth places or moves its mark, Shift+click deletes the nearest one), **Delete a tooth** / "Elimina un dente" (`aligners.preparation.numbering.delete-seed`, parameter `fdi`: a click on a tooth number, a tooth mark, a 3D tooth or the scan removes that mark at once, one undo step; on the scan the nearest mark within 4 mm wins, else the tooth under the click. It only removes the mark: the tooth is not marked missing. A tooth without a mark gives "That tooth has no tooth mark." and runs nothing; the controls are the hint and Close), **Change a tooth number** (`aligners.preparation.numbering.renumber`: pick the tooth, give the new number, Apply) and **Missing tooth** (`aligners.preparation.numbering.mark-missing`: pick the tooth, Apply). The controls of Mark a tooth:

- **Number the teeth in order** (button, with the checkbox "Include the third molars", which starts from the setting of Find the teeth). The command is `aligners.preparation.numbering.sequence`, sent once at the end, so the whole numbering is one undo step. The controls ask "Click tooth <n>" (or "Click a tooth on the scan to start" while the arch is not known, "All the teeth are numbered" at the end) and the hint says "Click the centre of the biting surface of the tooth shown, from the patient's right to the left. ### Separate teeth and gum (`aligners.preparation.segmentation.automatic`, "Separa denti e gengiva")

The leaf (menu label "Separate teeth and gum" / "Separa denti e gengiva") runs `aligners.preparation.segmentation.automatic` as **one undo step**, one arch at a time (an arch with a scan; with two arches each is separated on its own). It starts from the tooth marks (see Find the teeth) and paints every tooth on the scan with its own colour; the gum stays uncoloured.

Refusals (nothing changes, localised notice that names the arch, "Upper arch" / "Lower arch"):

- Fewer than 4 tooth marks on the arch: "<arch>: mark at least 4 teeth first." / "<arch>: segna prima almeno 4 denti."
- Marks missing on one side (right or left) or on the incisors: "<arch>: the tooth marks must cover both sides and the front teeth." / "<arch>: i segni dei denti devono coprire entrambi i lati e i denti anteriori."

Inspector (see "Inspector of a function"):

- Status: "Done" once every arch has its colours, and the result line "<n> teeth separated in <s> s" / "<n> denti separati in <s> s" of the last run (one line per arch that ran, read from the case; the same text is in the success toast "Teeth and gum separated" / "Denti e gengiva separati").
- Parameters: three sliders, in sight, with the unit-less value shown:
  - "Scan detail (faces)" / "Dettaglio della scansione (facce)": 5000 to 200000, default 30000.
  - "Tooth edge sensitivity" / "Sensibilità dei bordi dei denti": 0.01 to 1, default 0.2.
  - "Border smoothing" / "Levigatura dei bordi": 0.1 to 10, default 1.0.

  They are stored in the case settings (one undo step each), come back when the project is reopened, and are the same values **Run everything** uses.
- Automatic: the line "It starts from the tooth marks. Running it again erases the colours you painted by hand." / "Parte dai segni dei denti. Se lo esegui di nuovo, cancella i colori dipinti a mano.", then the run button ("Run", or "Run again" once done, as for every leaf).
- Manual corrections: **Tooth brush** (`aligners.preparation.segmentation.manual-brush`, key B: click or drag on the scan to paint the tooth chosen in the controls, with its radius; Shift gingiva, Ctrl fill the crown) and **Clean borders** (`aligners.preparation.segmentation.clean-borders`: the tooth, or 0 for all, and the smoothing rings, Apply). While either is open the viewport shows the scan.

Progress: the job runs in the status bar with the label "Separating teeth and gum" / "Separazione di denti e gengiva", the usual progress bar and cross to stop, and these sub-steps, in order: "Simplified scan" / "Scansione semplificata", "First separation" / "Prima separazione", "Tooth colours on the full scan" / "Colori dei denti sulla scansione completa", "Borders at full resolution" / "Bordi alla piena risoluzione", "Cleanup" / "Pulizia". Stopping leaves the arch as it was.

After a successful run:

- 3D teeth and the steps after it (and their check marks in the menu) are marked out of date: the check marks are removed and the toast "Results out of date" lists them (same wording as after a change of the tooth marks).
- The viewport switches to **Scan** view, so the new colours are visible (the 3D teeth toggle is described above).
- Seed-check problems and notes found by the run are kept in the case and shown again as a warning when the case is exported.

Reachable from CLI and MCP as the command `aligners.preparation.segmentation.automatic` (parameters `arch`, and the three separation parameters, defaulting to the saved settings); the whole automatic pipeline (`aligners.auto`) runs it after the numbering and orientation.

### 3D teeth (`aligners.teeth.build`, "Denti 3D")

The leaf (menu label "3D teeth", description "Gives you every tooth as a closed 3D model with its axis, and a gum that follows the teeth.") runs `aligners.teeth.build` with parameters `arch` (all, upper, lower) and `teeth` (FDI numbers to build again), as **one undo step**. It needs teeth and gum separated. Per arch:

- **All the teeth** (the default for an arch not built yet, or built with no hand corrections): closes every tooth as a 3D solid (measuring the teeth first), then builds the gingiva. The final position (setup) and the aligners of that arch are cleared, since they were planned on the old teeth.
- **Some teeth** (`teeth` given, or, without it, an arch already built whose teeth were corrected by hand with the brush or clean-up, plus teeth with colours but no solid and solids left without colours): the arch is measured again, only those teeth are closed again (a tooth with no colour left is removed, as a missing tooth), the gingiva is built again. The other teeth keep their solids. A rebuilt tooth keeps its planned movement in the world and its lock; a locked tooth goes back to rest; a removed tooth loses both. The aligners of the arch are cleared, the setup is kept.
- Then **Case analysis** (the diagnosis) runs on the new teeth.
- The scan is not deleted: where the viewport shows the 3D teeth, the built teeth of an arch replace its scan (see the toggle below). Wrong tooth numbers, or teeth of an arch not asked for, are refused before anything runs.

Manual corrections (the tool of its inspector): **Rebuild a tooth** (`aligners.manual.rebuild-tooth`): pick the tooth on the 3D teeth or on the scan, tick "Find the region again from the tooth mark" if its colours are wrong, Apply.

**Show the region** (`oa.tooth_highlight` / `oa.tooth_highlight_end` of the plugin; "Mostra la zona" / "Fine"). The first control of the manual corrections of the inspector, above the tools: two buttons, **Show the region** and **End**, and a line under them.

- Which tooth: the one selected in the viewport (a click on a 3D tooth, on its colour on the scan, or on its number). With no tooth selected the buttons are off and the line says "Click a tooth in the view to see the region of the scan it is built from."
- While it is on: the scan is drawn instead of the 3D teeth (whatever Scan / 3D teeth says), at the initial position (the stage on the timeline is not applied while it lasts), with the selected tooth in its colour and every other colour dimmed 65% towards grey (the plugin's `HIGHLIGHT_DIM`), the other arch dimmed as a whole, and the **margin line**, where the crown ends and the closed tooth is cut, as a yellow line (token `model_margin`, 2.5 pt with a dark halo) drawn in front of the mesh, so it is seen from any angle. The tooth also has the bold selection outline. The contact map and the colour layer do not show through; they come back at the end.
- The line under the buttons gives the tooth, the points of the region, its area and width, the reasons of the check (errors red, warnings yellow) and the length of the margin line; "No margin line" when nothing on the scan bounds the region (a tooth that is a shell of its own, as in the demo case, or the whole scan).
- It ends with **End**, Escape (first, before the selection is cleared), a selection that is not a tooth any more (deselect, click on empty space, another component), a manual tool opened, or another function selected. Clicking another tooth moves the view to it. Nothing is restored by hand: the view only overrides the model, the layers and the stage while it lasts.
- Menu law: the buttons only turn the view on and off. They run no step, change nothing in the case, add no undo step and open no dialog. The margin line is not stored in the case: it is worked out from the tooth colours (the 0.5 iso-line of the label smoothed six times on the surface, cut by marching triangles, the same cut as the rebuild of the tooth, `dca_algo::manual::margin_line`).
- CLI and MCP: the read-only command `aligners.manual.tooth-region` (parameters `fdi`, `detail`) returns the labelled vertices and faces (counts; the indices with `detail`), the check of the region (`region`, null with `region_error` when the arch cannot be measured yet), `message`, and the `margin` (points, segments, `length_mm`, `closed`, the loops, and with `detail` their points in scan coordinates). The window runs it on the current state without an undo step and draws the result.
- Differences from the plugin: no Edit Mode selection to grow or shrink the region (use the brush of "Separate teeth and gum"); the margin is a line in front, not a tube with yellow vertices; the camera is not framed on the tooth.

Out of date: the 3D teeth of an arch are out of date when its tooth colours, tooth marks or missing teeth changed since they were built (the brush, the clean-up, a mark placed, moved or deleted, a number changed, a tooth marked missing or present, the marks cleared, the numbering in order), or a tooth corrected by hand waits to be rebuilt. The build records what each arch was built from (`AlignersState::teeth_basis`: labels blob, marks, missing teeth) and the check compares it with the case (`AlignersState::teeth_out_of_date`); teeth built by an older version count only the teeth corrected by hand. Find the teeth and the separation run again clear the 3D teeth of the arch instead. The inspector then shows under the status a warning badge "Out of date" and the line "The tooth colours or tooth marks changed after the 3D teeth were built (<arches>). Run again to build them again; until then that arch shows the scan." (Italian "Non aggiornati", "I colori o i segni dei denti sono cambiati dopo la costruzione dei denti 3D (<arcate>). …"). Run again builds the arch again and it is up to date; "Rebuild a tooth" also brings it up to date once no tooth corrected by hand is left and the marks are those it was built from.

Progress: the job runs in the status bar with the label "Building the 3D teeth" and the usual progress bar and cross to stop. Success toast "3D teeth built" with the detail "<n> teeth built (upper <u>, lower <l>), gingiva for upper and lower." (the last part reads "gingiva for upper", "gingiva for lower" or is left out when no gingiva was built; for a partial rebuild <u> and <l> count the rebuilt teeth).

Viewport toolbar, right after the arch toggles: a two-segment toggle **Scan** / **3D teeth** (role radio button; tooltips "Show the scans of the arches" / "Show the built teeth and gingiva instead of the scans"). The default is 3D teeth, which show only for arches that were built; an arch not built keeps its scan. The scan is shown whatever the choice while the brush, the clean-up or the seed tools are open (they paint and read the scan labels) and while the **Contact map** layer is on; the toggle then shows Scan and its tooltip adds "The scan is shown while a tool works on it or the contact map is on". Closing the tool or switching the contact map off returns to the 3D teeth. A tool that picks a tooth works on the 3D teeth. The choice is kept for the workspace session.

Tooth marks: the seed markers are not drawn over an arch whose built teeth are shown (the plugin hides its seeds after building the teeth); they are drawn in the Scan view and while a tool shows the scan. The bite scan stays visible and the number chips stay.

Out-of-date arch: an arch whose 3D teeth are out of date (see "Out of date" above) shows its **scan**, with its colours and tooth marks, even with 3D teeth chosen, so the corrections stay in sight (also after reopening the project); its number chips are placed as in the Scan view. The toggle tooltip then adds "Arch changed by hand after the 3D teeth were built (<arches>: tooth colours or tooth marks): it shows the scan until you build the 3D teeth again". Once built again, the 3D teeth replace the scan as before.

Stages: with 3D teeth shown, a later stage poses each tooth by its pose of that stage, the stage 0 ghost draws the rest position, and the **gingiva deforms** with the teeth (blended by weights on the teeth). The weights are slow the first time: they are computed in the background and the gingiva is drawn at rest until they are ready. The scans always stay at rest. Tooth number chips follow the stage poses (see above).

Reachable from CLI and MCP as the command `aligners.teeth.build`; the whole automatic pipeline (`aligners.auto`) runs it after the check of the segmented teeth. `render` takes `model` and `stage` (see Arch selection).

### Final position: parameters, result, reset, move a tooth (gap map 7.1 d/e, 7.2, 7.3)

The inspector follows the plugin's page (`page_finale`), in the order of the menu law:

- **Under the status**: "Bite first" when needed (see above), then the result of the last computation of each arch, named when both have one: "Expansion: x mm per side in the posterior teeth, y at the canines", "Incisors: ±x mm (+ forward)", "IPR: x mm on n contacts", the lines of its log the plugin shows (teeth aligned, evaluation, locked tooth off the line, teeth held, teeth that move, midline, derotation not complete, space left), and "Crowding not resolved: x mm" as a warning badge. It is kept in the case and goes with the final position.
- **Parameters** (`aligners.settings.setup`, one undo step per change, a slider when it is let go; nothing is computed): "Teeth" (incisors and canines / up to the premolars / all), then five folded groups as the plugin's: Arch line and tolerances; Teeth held and midline; Space (order, the expansion of the arches of the case, advancement, retraction, close the gaps); IPR (zone, per surface, enamel fraction); Vertical movements. Plugin defaults and slider ranges; then "After changing the parameters, run the final position again." and "The values to confirm must be checked by an orthodontist."
- **Manual corrections**: Move a tooth, Arch line, then "Back to the initial position" (`aligners.planning.setup.reset`: every tooth back at rest, IPR, result and aligners of the final position go; locks, the drawn line and the settings stay; disabled without a final position).
- **Move a tooth**: the tooth (click or number; a tooth without 3D teeth asks for one). For a measured tooth: each clinical component (mesial/distal, buccal/lingual, extrusion/intrusion, crown torque, crown tip, rotation) with its movement now between − and + (one step each: "Step (mm)" and "Step (degrees)", plugin defaults 0.1 mm and 1°, kept in the case); "Lock the tooth in the setup" (the tooth's own lock, a command each way) and "Reset the tooth"; the notes on how predictable the movement is (`movement_flags`, warning colour, danger for high risk); the exact values of the movement, prefilled, and "Write the exact values" (`exact`: the whole movement from rest); "Adjust the stage shown", "Refuse a collision", Close. A lock alone gives no notification.

### Final position: arch line and final ghost (gap map 7.5, 7.6)

**Arch line** ("Linea d'arcata", the plugin's `oa.arch_line_show` / `_edit` / `_apply` / `_reset` / `_hide`): a tool of the **Manual corrections** of Final position, after Move a tooth (command `aligners.planning.setup.line`). Opening it selects Final position and runs nothing.

- The line shown for an arch is the one the final position aligns the incisal edges, canine tips and buccal cusps on: the line drawn by hand when there is one, else the line of the last computation. It is drawn for every arch shown, in front of the teeth (2.5 pt `model/arch-line` with a dark halo), as a smooth curve through 11 points spread evenly along it (the plugin's 11 control points, automatic Bézier handles). The points of the arch Apply works on are filled, those of the other arch outlined. While the line is shown the teeth at their final position are ghosted (as the plugin shows them).
- A point is dragged with the left button (the pointer becomes a hand over it); it moves on the occlusal plane through it (seen edge-on, on the plane of the screen). The right button still orbits. Moved points stay in the tool, not in the case, until Apply; they are forgotten when the line in force changes (applied, undone, computed again).
- The panel: one line on what the line is; Upper / Lower when both arches have a line; "Line drawn by hand." or "Automatic line."; "Points moved, not applied yet." in the warning colour; the check "Compute the final position again (teeth moved by hand lose their corrections)", on by default (the plugin's `recalc`); **Apply the line** (primary): the curve through the points, 24 points per segment as the plugin reads its curve back, is stored as the drawn line and, with the check on, the final position of the arch is computed again on it with the parameters in force, in one undo step (toast "Final position computed on the arch line: compute the aligners again."; without it "Arch line saved: the next final position follows it."); **Back to the automatic line**: drops the drawn line and computes the final position again (with only moved points it just forgets them); **Hide the line** / **Show the line**: only what the view draws; Close.
- Every later computation of the final position (its Run button, Run everything automatically) follows the drawn line until it is taken back; it moves with its arch (bite, gizmo) and goes when the scan or the tooth colours of the arch are made again.
- Before the first computation of the final position there is no line: the panel says "There is no arch line yet: compute the final position first." (the plugin shows a line from the cusps at rest then).
- CLI and MCP: `aligners.planning.setup.line` with `arch`, `points` (case coordinates; none = back to the automatic line) and `recompute` (default true).

**Final ghost** (layer "Target position" of the toolbar, the plugin's `ghost_final`): a toggle. On, at any stage of the timeline, the teeth are ghosted at their final position in `model/target` at 25 % opacity, not pickable: the 3D teeth shown, or the crowns of a scan (its gingiva left out). Each tooth is moved exactly as a stage moves it: its final pose relative to its rest frame, about its centre of resistance. A case without a final position keeps the layer off with the notice "There is no final position yet: compute it to see where the teeth end up." A hidden arch hides its ghost.

### Aligners: parameters, calendar, result, slow a tooth (gap map 8.1, 8.2, 8.3)

The inspector of **Aligners** (`aligners.planning.aligners`) follows the plugin's page (`page_allineatori`), in the order of the menu law:

- **Under the status**: the result of the last aligners of each arch, named when both have one: "n aligners"; "x days (about y months)" and "From dd/mm/yyyy to dd/mm/yyyy (worn 22 hours a day)" from the calendar of the stored aligners with the calendar settings of the case (no start date: today); "Pattern: …; complexity: …" (the pattern used, the automatic one resolved); "Slowed teeth: 31 (0.50), …"; "Collisions left: n (see the report)" as a warning badge; "Overcorrection applied to the final movement". It is kept in the case (`AlignersState::staging_results`) and goes with the aligners of its arch (reset of the final position, new tooth colours, a re-plan at a visit).
- **Parameters** (`aligners.settings.staging`, one undo step per change, a slider when it is let go, the date when its field is left; nothing is computed): Periodontium (healthy, stage I, II, III), Pattern (automatic, simultaneous proportional, simultaneous X, sequential distalisation 1/2, structured); "Calendar": Aligner change (fixed interval / adaptive 7/14 days), Days per aligner (5 to 21, fixed only; the adaptive choice shows what decides 7 or 14 days), Start of treatment (`YYYY-MM-DD`, empty = the day the calendar is made; a date that is not one is refused); then the folded group "Largest movement per aligner": translation, vertical, rotation, rotation of canines and premolars, torque and tip, largest move of the crown, avoid collisions, contact tolerated, overcorrection. Plugin defaults and slider ranges; then "After changing the parameters, run the aligners again." The run button runs the aligners and their calendar with these settings.
- **Manual corrections**: **Slow a tooth** ("Rallenta un dente", the plugin's `oa.tooth_speed`) on the tooth selected in the view (component selection): without a tooth "Select a tooth in the view to slow it down."; with one, its speed now ("Normal speed" or "Slowed: speed 0.50"), the slider Speed (0.2 to 1, default 0.5 as the plugin's dialog), **Slow the tooth** (`aligners.planning.tooth-speed`, rounded to two decimals; the aligners of its arch are computed again in the same undo step when the arch has a final position) and, for a slowed tooth, **Back to the normal speed**; then the list of the slowed teeth. Selecting the function or the tooth runs nothing.
- CLI and MCP: `aligners.settings.staging` (the fields of the parameters and `interval_policy`, `interval_days`, `start_date`), `aligners.planning.tooth-speed` (`fdi`, `speed`; null or 1 = normal), `aligners.planning.aligners` (`start_date`, `interval_days`, `policy` override the case settings for that run). The schedule and the exports use the case's start date, days and policy when they are not given.

### Clinical review (`aligners.review.classify`, "Revisione clinica"; gap map 9.1, 9.2, 10.1)

The classifications the program proposes from the evidence, which the clinician confirms or changes before production (the plugin's `oa.classify` page, without the AI classifier).

- **Placement**: a leaf of the Plan group, after Aligners, and the ninth step of the workflow (done when every arch of the case holds records; the footer reads `done/9`). The records are the case's: `AlignersState::review`, saved with the project and cleared with the arch (clearing reason "clinical review").
- **Run** (`aligners.review.classify`, parameter `arch`: all, upper or lower; one undo step): makes the records of every arch that has a case analysis. Per arch: case difficulty, aligner pattern, treatable with aligners only; per tooth, when the arch has a final position: movement risk and attachment; for every tooth: crown measures and tooth type (numbering). A decision already taken stays when the computed value of its record does not change. In Run everything automatically it runs after the aligner sequence and before the calendar, as in the plugin; when the staging pattern is automatic and the pattern in force of the review differs from the one the aligners were made with, that arch is staged again in the same undo step (a notice says so). Selecting the leaf runs nothing (menu law).
- **Inspector** (section order of "Inspector of a function"): the status badge, under it "To review: n. Decided: n." and the count of items with a note to check; the Run button ("Run", "Run again" once done); then the manual corrections.
- **Filter**: four segments, as the plugin: All, To review, With a note, Selected tooth (the tooth selected in the view; without one "Select a tooth in the view to see its items.").
- **List**: one row per record, a status icon (check when decided, warning when to review with a note, circle when to review) and its text. Choosing the row of a tooth selects that tooth in the view. The chosen item shows its title, the computed value, the lines of the method (the evidence), the proposal, the note as a warning badge when it asks for a check, and its decision ("Confirmed", "Computed value kept", "Changed" with the time in UTC, or "Preset: value, to review").
- **Decisions** (one undo step each): "Confirm" (primary: accepts the proposal, `aligners.review.decide` action `confirm`); a radio per option of the item (`aligners.review.set-value`: only one of the item's options); "Back to the proposal" once decided (`reset`). The action `computed` of the command keeps the computed value. Keys of the records are like `lower:attachment:33`, `upper:complexity:arch`.
- **Bulk** ("All together", `aligners.review.bulk`): "Confirm those without a note" (`confirm_unflagged`: the items with a note to check are never confirmed together) and "Back to the proposals" (`reset`). There is no confirmation dialog: undo is available.
- **What the review feeds**: the attachments in force go to the aligner calendar (the "apply the attachments" event before aligner 1), to the Aligners inspector calendar, to the `.ics` of the STL export, to the export package and to the report, which has a review table (English and Italian text). The aligner pattern in force is used by the next aligner sequence.
- CLI and MCP: `aligners.review.classify`, `aligners.review.decide` (`key`, `action`), `aligners.review.set-value` (`key`, `value`), `aligners.review.bulk` (`mode`).

## 7. Accessibility

- Contrast (dark): text/primary on panel 14.0:1, text/secondary 6.9:1, amber text 8.7:1, blue 6.5:1, on-amber on amber 9.2:1; inputs' `border/strong` 3:1 against panels. Light: primary 16.5:1, secondary 7.0:1, amber-text 5.9:1, blue 5.3:1.
- `text/disabled` intentionally below 4.5:1 (disabled controls are exempt) but always paired with a lock or the disabled state explanation.
- Every focusable widget has the 2 pt focus ring; tab order follows reading order (top bar, menu, viewport toolbar, timeline, inspector).
- Patient privacy: aliases only in UI and exports; diagnostics bundles exclude scan geometry and aliases.
